- **fix(search):** the `Settings -> Security -> Blocked Providers` policy is now enforced on the search surface. `GET /v1/search` no longer advertises a blocked search provider, and `POST /v1/search` rejects an explicitly-blocked provider with HTTP 403, skips a blocked provider during auto-selection, and excludes blocked providers from the cost-sorted fallback. Because the MCP `omniroute_web_search` tool dispatches through `POST /v1/search`, this closes the bypass for both the REST API and the MCP tool (fixes [#10863](https://github.com/diegosouzapw/OmniRoute/issues/10863)).
