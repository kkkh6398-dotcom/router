- **fix(db):** call-log rotation now fails closed on SQLite corruption instead of swallowing it. When `rotateCallLogs()` hit a `SQLITE_CORRUPT` ("database disk image is malformed") error it only logged the message, so the ~60s rotation timer kept re-issuing DELETEs against the already-malformed pager (risking wider damage) while `/api/db/health` stayed fully green and operators only noticed when artifacts silently stopped rotating. Rotation now detects the corruption signal, fences all further rotation writes until the database is restored, and records the cause; the DB health check folds a live fence into an `integrity_check_failed` issue so `/api/db/health` reports degraded (even when `quick_check` is skipped on slow storage). Per the maintainer's scoping, this is deliberately root-cause-agnostic and does not attempt repair: a live auto-`REINDEX`/`VACUUM` on a single-writer corrupt file is worse than the failure, so recovery stays a deliberate operator restore from a known-good backup.
