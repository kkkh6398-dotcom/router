- **fix(relay):** the Cloudflare proxy-relay worker now resolves `x-relay-path` through the shared SSRF-safe `resolveRelayTarget()` guard instead of concatenating it onto the validated target. PR #4643 applied that guard to the Deno and Vercel workers; the Cloudflare generator, ported separately from upstream `decolua/9router` PR #1360, kept `fetch(targetBase + relayPath)`, which let an attacker-controlled path re-point the request past the just-checked host via userinfo (`/x@evil.com`), a backslash (`\evil.com`), or a protocol-relative path (`//evil.com/x`). The guard is embedded under a literal `const resolveRelayTarget =` binding so the hardcoded call site survives SWC minification (#6149), with a regression test pinning that property (fixes [#10935](https://github.com/diegosouzapw/OmniRoute/issues/10935)).
