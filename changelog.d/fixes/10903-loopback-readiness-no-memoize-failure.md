- **fix(providers):** the loopback model-sync readiness gate no longer memoizes a failed probe. Previously `ensureLoopbackServerReady` cached its promise unconditionally, so a single failed readiness probe at boot cached a rejected promise forever, sending every subsequent model-sync self-fetch to the in-process fallback permanently (no probe ever ran again) and re-logging the failure once per waiting caller. The cache is now cleared on rejection so the next caller re-probes and self-heals once the server accepts connections, while a resolved probe stays cached so a healthy process still runs exactly one probe sequence. The readiness-failure warning is throttled to at most once per minute across callers (fixes the ~270-log-lines-in-26h symptom).
