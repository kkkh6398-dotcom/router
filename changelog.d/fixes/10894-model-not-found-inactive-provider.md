- **fix(model):** an unrecognized bare model id with a known vendor prefix (e.g. `claude-unrecognized-*`, `gemini-*`) no longer gets force-routed to that vendor's provider when the operator has not configured it. `resolveModelByProviderInference` inferred `anthropic` / `gemini` from the name prefix unconditionally, so an install running only OpenAI (or other providers) had the request pinned to an unconfigured `anthropic` provider and failed with a misleading `[401] Missing API key` instead of a truthful `model_not_found` (404). Prefix inference is now gated on the provider actually being in the active-provider set (a null/empty set, meaning no filtering, still accepts the inference) (fixes [#10856](https://github.com/diegosouzapw/OmniRoute/issues/10856)).
