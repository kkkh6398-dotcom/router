- **fix(auth):** add `["opencode", "opencode-zen"]` to the provider credential search pairs (#10899). OpenCode is served by two identities: the no-auth `opencode` id the user's connection card stores the key under, and the `opencode-zen` APIKEY gateway the model layer resolves the `opencode/<model>` prefix to. An auto-combo target resolving to `opencode-zen` searched `provider_connections` for `opencode-zen` only, found nothing, and dropped the target (503 `ALL_TARGETS_SKIPPED`) even though the key sits on the `opencode` row. The new pair lets a lookup under either id find the other (same operator account, requested id first), mirroring the existing `nvidia`/`nvidia_nim` and `antigravity`/`agy` pairs. No cross-account or cross-user credential exposure: resolution stays scoped to the requesting context, and the two ids are the same owner's OpenCode identities.
