- **fix(models):** persist `apiFormat`, `targetFormat`, and `supportsVision` overrides for catalog models (#10898, #10871). A `PUT /api/provider-models` carrying only these fields for a non-custom catalog model fell through to `404 Model not found`, so an operator could not pin a model's wire protocol or vision capability. The three fields now flow into the `ModelCompatPatch`, merge into `ModelCompatOverride` (delete on falsy, set otherwise), and resolve at runtime through the custom → compat-override → synced precedence ladder in `resolveRuntimeFormats`. Compat overrides are read/written under the canonical provider id (`resolveProviderAlias`) so an override set under an alias resolves consistently. No secret is persisted (all three are non-sensitive enums/bool) and no new read audience is exposed.
